# Mira ID

**One identity. Across Mira.**

Mira ID 是 Mira 产品生态的统一账号与身份入口。

它为用户提供一致的登录体验、设备管理、安全设置与服务授权，让 Mira Desktop、Mira Mobile 及其他 Mira 服务能够安全地识别同一个用户。

Mira ID 的设计理念是：

**身份应该始终可靠，但不应该成为用户的负担。**

## 1. 品牌定位

| 项目 | 定义 |
|---|---|
| 产品名称 | Mira ID |
| 中文名称 | Mira 账号 |
| 工程名称 | cloud-auth（保留） |
| 英文标语 | One identity. Across Mira. |
| 产品类别 | 统一身份与账号服务 |
| 目标用户 | Mira 产品生态用户 |
| 品牌角色 | 安静、可靠、精致的基础服务 |

Mira ID 不是新的社交账号体系，也不是面向企业的通用 IAM 平台。

它是 Mira 用户进入个人 AI 生态的统一身份。

**工程层保持 Cloud Auth，产品层统一呈现 Mira ID。**

## 2. 本轮项目目标

这是一轮轻量品牌升级，不是架构重构。

1. 将旧产品名称「云账号中心」升级为「Mira ID」。
2. 引入全新的指纹品牌图标。
3. 统一登录、账号管理、设备管理与服务授权页面的视觉语言。
4. 优化界面文案与信息层级，减少后台系统式表达。
5. 统一 favicon、浏览器标题、品牌资源与基础元信息。
6. 保持原有认证、授权和跨端协议兼容。

不以增加功能数量作为本轮成果。

## 3. 视觉识别系统

### 3.1 品牌图标

采用已提供的 **Mira ID 指纹图标**：深海军蓝圆角方形底座、象牙白抽象指纹、柔和连续的线条。不使用锁头、盾牌等传统安全标识作为主 Logo。

指纹表达的是用户身份的独特性与连续性，不意味着产品已经实现生物识别登录。

图标来源：`Mira-ID-Web-Assets.zip`。开发前检查各资源的透明背景、清晰度与视觉一致性。

### 3.2 视觉颜色

| 用途 | 建议色值 |
|---|---|
| 品牌深海军蓝（`--mc-brand-navy`） | `#151A2C`（以正式素材包为准） |
| 指纹象牙白（`--mc-brand-ivory`） | `#FFF6ED`（以正式素材包为准） |

品牌颜色只通过品牌 Token 管理，仅用于 Logo 标识容器等品牌表面。不覆盖整个应用已有的背景、正文和状态色（`--mc-text`、`--mc-surface-*`、`--mc-success/warning/danger/info-*` 等保持不变）。Logo 使用素材包原始文件，不重新绘制。

### 3.3 设计原则

**克制，而不是贫乏。**

- 保持清晰的信息层级和充分留白。
- 不使用大面积高饱和渐变。
- 减少不必要的卡片嵌套与装饰分隔线。
- 适度圆角，避免过度胶囊化。
- 支持桌面与移动屏幕。
- 尽量保持 Mira 产品家族视觉一致性。
- 保留清晰的焦点、错误、加载和交互状态。
- 保证文字对比度、键盘操作和基本无障碍能力。

**产品应当显得精致，而不是复杂。**

## 4. 品牌命名与界面文案

| 原有表述 | 新表述 |
|---|---|
| 云账号中心 | Mira ID |
| Mira Cloud Account（产品标题） | Mira ID |
| 云账号登录 | 登录 Mira 账号 |
| 云账号管理 | 账号设置 |
| 已授权设备 | 登录设备（仅在语义确实相同时） |
| 退出云账号 | 退出登录 |
| 关联服务 | 已连接服务（仅在表达真实连接状态时） |

不要对技术字段进行全局字符串替换。Cloud Session、Mira Device、OAuth Client、Service Credential 等工程术语保留原有语义。

不得把登录设备、已注册设备、有效会话或已授权设备混为同一个概念。

### 文案风格

- 使用简洁、自然的中文。
- 不向普通用户展示不必要的身份认证术语。
- 不夸大安全能力。
- 对失败状态给出明确、可理解的说明。
- 避免冗长的功能介绍。

示例：

- **欢迎回来**：登录 Mira 账号，继续使用你的服务。
- **登录设备**：查看当前仍具有有效登录会话的设备。
- **应用授权**：查看并管理你授予其他 Mira 服务的访问权限。

## 5. 页面升级范围

本轮在现有 `apps/web` 中实施，不新建前端工程。

- **5.1 品牌首页 `/`**：呈现 Mira ID 的产品身份；不改变现有会话判断逻辑。
- **5.2 登录页面 `/login`**：显示 Mira ID 图标，统一标题、输入框与按钮样式，清晰呈现错误与加载状态，保留现有身份认证流程。不得自行增加第三方登录、公开注册、Passkey 或其他认证方式。
- **5.3 账号页面 `/account`**：个人账号的轻量管理入口（账号概览、登录设备、账号安全、已连接服务），不堆叠复杂模块。
- **5.4 设备页面**：继续使用服务端权威数据；准确区分设备、会话及授权关系；不通过最近活动时间猜测有效登录；不把 Host 租约状态误称为网络实时在线；不改变既有撤销语义；不因前端隐藏历史记录而删除服务端安全记录。
- **5.5 应用授权与关联服务**：保留真实授权状态；不凭空生成连接状态；不把短时服务凭证当作持续授权；不展示敏感凭据；不改变已有授权范围和撤销行为。

## 6. 工程边界

目标仓库：`https://github.com/uichat-mira/cloud-auth`

- `apps/api`：Fastify 身份认证服务。
- `apps/web`：Vite + React + TypeScript 账号门户。
- `packages/contracts`：跨端共享契约。

### 允许修改

- 品牌图标及静态资源。
- 前端页面标题、产品名称和说明文案。
- 品牌相关 CSS / Design Tokens。
- 登录页和账号门户的视觉布局。
- Favicon、PWA 图标与浏览器元信息。
- 与本次品牌升级直接相关的前端测试和文档。

### 本轮不允许修改

- API 路径与请求响应契约。
- Cloud Session 签发、续期和撤销语义。
- OAuth、PKCE、JWKS 与服务凭证。
- 数据库 Schema 或身份记录。
- Desktop / Mobile 现有客户端协议。
- Host 授权及 Relay 业务边界。
- 生产域名和认证回调地址。
- 与品牌升级无关的业务功能。
- Local、Direct 和 Tailscale 的独立使用路径。

除非发现实施所必需的明确问题，否则不要触碰 `apps/api` 和 `packages/contracts`。

## 7. 实施原则

- 最小且可验证的改动。
- 复用现有组件和主题变量，不另起 UI 框架。
- 不因视觉改动引入新的认证逻辑。
- 不使用虚构数据作为生产界面内容。
- 不静默吞掉错误或隐藏真实状态。
- 不擅自合并或部署生产。

## 8. 验收标准

### 品牌验收

- [ ] 用户可清楚识别 Mira ID 名称与指纹图标。

- [ ] 页面标题、Logo、favicon 与浏览器元信息一致。

### 功能回归

- [ ] 现有登录流程不回归。
- [ ] Session 恢复、续期和退出不回归。
- [ ] 登录设备页面仍使用正确的数据与状态。
- [ ] 设备撤销与应用授权行为不回归。
- [ ] OAuth 授权页面仍正确识别客户端及权限。

### 工程验证

至少执行 `pnpm run check`，并根据实际变更选择对应测试，记录通过、失败或未执行的情况。浏览器验收应覆盖登录前、登录后、加载失败、空状态和移动端布局。不得以静态截图替代真实功能验证。
